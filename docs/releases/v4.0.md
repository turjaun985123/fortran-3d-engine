> 4 jobs green, verified twice at job level (see checklist).

Forge3D 4.0 is the Animation Platform release: a `.f3d` file whose
first statement is `film` becomes a story written in sentences —
characters, actions, dialogue, camera moves, in written order —
compiled to a frozen Timeline IR contract, rendered by the engine
as flat 2D characters inside real 3D environments, previewed with
real playback, and exported to video with subtitles. Character
rigs and action sets are plugins: external packages on disk. The
stickman engine is the first plugin, not a built-in.

A film still fits on a screen:

```f3d
film "Saturday Market" size 1280 720 fps 24

scene "market" background white transition fade 1 second
camera at 0 3 10 look 0 1 0
plane ground gray at 0 -2 0 size 16
cube stall red at 3 0 0 size 2
place stall-front at 1 0 2
character lloyd blue at -5 0 2 tall head round wears cap red
character mira pink at 4 0 2 kid head round hair bun

lloyd walks to stall-front in 4 seconds ease smooth
with camera follows lloyd
lloyd says "Good morning, Mira!" for 2 seconds
mira says "The mangoes look fresh today!" for 3 seconds

render "saturday-market.mp4"
```

## Highlights

- **Film mode** — the `film` header, `character` / `place` setup
  lines, and cues that play in written order, with `with`,
  `together`, `at <time>` and `wait` as the only sequencing
  modifiers. Built-in sentence verbs (`walks to`, `waves`,
  `sits on`, `picks up`, …), custom actions defined once with
  `it` as the actor, camera cues (`follows`, `zooms`, `pans`,
  `orbits`, `looks at`), dialogue with estimated-or-written
  durations, captions/titles, scene transitions, timeline
  `repeat` blocks and `let` variables. New diagnostics
  E206–E214 / W203–W205, append-only.
- **Timeline IR v1, frozen under ADR-5** — `f3dc build` emits
  `<name>.timeline.json`: integer frames at a rational fps,
  half-open spans, a cast table carrying plugin ids and rig
  records, per-scene spans, resolved action keys, camera tracks,
  dialogue cues and markers. Spec: `docs/TIMELINE-FORMAT.md`.
  Evolution is additive-only from the Wave 2 freeze.
- **Engine film rendering** — `engine3d <file>.timeline.json`
  renders whole films: procedurally generated stickman figures
  (proportions, FK, accessories) inside the v3 3D renderer,
  channel blending, camera tracks, fade/dissolve blending,
  deterministic at any thread count (CI gates G3d/G3e pin the
  golden film's frames and sequence digest).
- **Preview playback** — transport bar with deterministic seek
  and scrub, `GET /__timeline`, subtitle overlay, per-character
  action lanes, a diagnostics drawer, and the playhead kept in
  the `#t=` URL hash across edit-reloads.
- **Plugins are external packages** — `plugins/<id>/plugin.json`,
  loaded at run time (`F3DC_PLUGIN_PATH`; set-but-empty loads
  nothing). Stickman's rig, verb set, prop schemas, expression
  codes and all 20 parametric templates are data in
  `plugins/stickman/`; the core keeps only the loader, registry
  and a generic template interpreter. A film naming an unloaded
  plugin fails cleanly with E214; malformed packages are skipped
  with W205.
- **Video export + `.srt`** — film-mode `--video` /
  `render "name.mp4"` assembles the film's frames at the film
  fps via ffmpeg, with a loud frames-kept warning when ffmpeg is
  absent (exit 0, never a silent success); `f3dc build` writes
  a `<stem>.srt` sidecar from the dialogue with exact rational
  timing.

## Assets

Linux binaries attached as release assets (built by CI from
the tagged tree):

- `bin/f3dc` (built by `make f3dc`)
- `bin/engine3d`

Building from source needs Flang 18 (`flang-new-18`) and
clang 18: `make f3dc`. There is no Python requirement at build
or run time — as in 2.0 and 3.0, there is zero Python in the
repository. Plugin packages are data in the repo tree
(`plugins/`), not release assets.

## Upgrade notes

- **Nothing breaks.** Film mode is opt-in by the `film` first
  statement; every pre-4.0 program compiles, desugars and
  renders exactly as in 3.0.0, and the 3-line contract
  (`cube red` / `spin it` / `render`) is byte-identical.
- **The default renderer did not change** (still v3; legacy
  still available bit-exact via `--renderer legacy`).
- **New build artifacts are conditional:** a source with
  animation authoring now also produces `<name>.timeline.json`,
  and a film with dialogue also produces `<name>.srt`. Stills
  produce neither, exactly as before.
- **Plugins must be present to compile films.** A checkout (or
  install) that drops the `plugins/` directory will fail film
  compiles with E214 — by design; non-film scenes are unaffected.
  `F3DC_PLUGIN_PATH` points the compiler at other package
  locations.

## Known limitations

- **The `humanoid` plugin is a skeleton only** — rig record,
  channels, verbs, `speaks`; no templates, no rig channels, so
  its actions stay unresolved by design (depth: Waves 19–24).
- **`slide` / `wipe` transitions render as a cut** in the engine
  (with a note); `fade` and `dissolve` are real blends. The
  transition variant (`fade black`, `slide left`) is not carried
  in Timeline IR v1.
- **Core verbs on characters are `resolved: false`** — closed-form
  object verbs evaluated by the engine's animation path, not
  resolved to rig-channel keys.
- **No TTS, no speech bubbles, no burned-in subtitles.** `says`
  is text + timing + style; dialogue surfaces in the preview
  subtitle overlay and the `.srt` sidecar. Captions/titles have
  no Timeline IR v1 record (recorded freeze decision).
- **Multi-scene films do not preview** — the preview compiles a
  single scene; single-scene films preview fully.
- **`sit` uses a generic 0.5 seat height** (no lookup of the
  named object's geometry).
- **XR real-device check still open**, carried over from 3.0:
  the XR sidecar is headless-verified (9/9), but an immersive
  session still needs a human with a headset (see
  `docs/XR-CHECK.md`).
