# Forge3D v3.0.0 — Real Pipeline

> **Draft — not yet released; the v3.0 code wave is UNTESTED pending the verification pass, and this release is created only on the maintainer's nod**

Forge3D 3.0 is the Real Pipeline release: the v3 rasterizer is
now the default renderer, with a real colour and shadow
pipeline, a full texture and material system, quaternion
animation, and a typed compiler — while the legacy renderer is
frozen, unchanged, and still available bit-exact.

A scene still takes three lines:

```f3d
scene size 640 480 background black
camera at 4 3 6 look 0 0 0
cube spinner red at 0 0 0
```

## Highlights

- **v3 rasterizer by default, legacy frozen** — new renders go
  through the v3 pipeline: a unified rasterizer stage with a
  linear `real32` framebuffer and perspective-correct
  interpolation. The legacy renderer is not modified; it stays
  pinned to its golden and is selectable with
  `--renderer legacy` (see Upgrade notes).
- **Real shadows and colour pipeline** — shadow-mapped lights,
  a linear-workflow colour pipeline with proper output
  encoding, and per-light controls replace the flat legacy
  lighting model on the v3 path.
- **Full texture and material system** — image textures,
  materials with maps and surface properties, and texture
  sampling in the v3 rasterizer, shared by the native engine
  and the browser runtime.
- **Quaternion animation** — rotations animate with quaternions
  and slerp interpolation, with keyframed clips at a per-clip
  frame rate, instead of Euler-only interpolation.
- **Typed compiler with incremental builds** — `f3dc` now
  builds a typed AST/IR, validates scenes in a dedicated
  validator stage, and recompiles incrementally: unchanged
  inputs are not rebuilt. Property-based tests cover the
  compiler stages.
- **ES-module runtime, honestly sized** — the browser runtime
  ships as ES modules. The honest total size is **139,928
  bytes** — the whole runtime, not a cherry-picked core file.
- **Compressed PNG, binary PPM, and `f3dc profile`** — PNG
  output is compressed, binary PPM (`P6`) output is available
  alongside the text format, and `f3dc profile` reports where
  compile and render time goes.
- **Fuzzing and hardening** — the scene parser, model loaders
  and image codecs are fuzzed, and malformed inputs fail with
  diagnostics rather than crashes on the hardened paths.

## Assets

Linux binaries attached as release assets (built by CI from
the tagged tree):

- `bin/f3dc` (built by `make f3dc`)
- `bin/engine3d`

Building from source needs Flang 18 (`flang-new-18`) and
clang 18: `make f3dc`. There is no Python requirement at build
or run time — as in 2.0, there is zero Python in the
repository.

## Upgrade notes

- **The default renderer changed: legacy → v3.** Renders will
  differ from v2.0 output by design — different rasterizer,
  lighting, shadows, colour encoding and interpolation. This
  is the intended 3.0 picture, not a regression.
- **Legacy output is still available, bit-exact.** Pass
  `--renderer legacy` to get the frozen legacy renderer,
  pinned to the strict golden sha256
  `28b6a81dd052a740f3a395ea41b3e0dd37e02eeff585a56fa90e05ac7697cec1`.
  That golden has never been re-baselined.
- **`.scene` v1 files are still readable.** Existing version-1
  scene files load unchanged; the versioned, keyed scene
  format adds v3 data without orphaning v1 files.
- Scenes using sprites, text or particles still render — the
  v3 path falls back to legacy for those scenes (see Known
  limitations).

## Known limitations

- **XR real-device check still open.** The C4 item carried
  over from the v1 parity matrix remains unconfirmed: the XR
  sidecar is tested headlessly with mocks, but an immersive
  session still needs a human with a headset (or an XR-capable
  Android phone + Chrome), using `examples/xr-check.html` and
  `docs/XR-CHECK.md`. This is the same open item as in 2.0.
- **Adam7-interlaced PNGs are rejected.** Interlaced PNG
  textures using the Adam7 scheme fail with a diagnostic
  rather than decoding; re-export the image non-interlaced.
- **Sprites, text and particles fall back to legacy.** Scenes
  using those features are rendered by the legacy path, not
  the v3 rasterizer, until they are ported.
- **Near-plane-crossing triangles are dropped in v3.** A
  triangle that crosses the near plane is discarded whole
  rather than clipped, which can make geometry very close to
  the camera pop out instead of slicing.
